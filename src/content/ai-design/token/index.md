# 你不知道的大模型：从 Token 到下一个 Token

用了很长时间的 AI，我却一直不明白大模型到底是什么。它对我来说像一个黑盒子，我知道怎么输入问题，也能看到它给出答案，却不知道文字进入模型以后发生了什么。

越来越用 AI，越发现了自己的局限性，热点做什么，我就做什么，不清楚这样做的原理，久而久之没有太大进步。

这段时间，我重新读了一些大模型的资料，决定将这些问题进行一步步拆解，在自己学习的同时，也能做一个 AI 的简单认知介绍。

## 什么是大模型

### 什么是模型

在理解大模型之前，我们先理解，什么是模型。模型本质其实就是一个函数，y = f(x)，输入一个 x，输出一个 y，这是我们学过最简单的一个函数，也叫做模型。比如，x 是体重身高，y 是 BMI，叫模型。x 是今天的所有气象数据，y 是明天会不会下雨，所谓模型，本质上就是一种输入到输出的映射关系。

在计算机里，最简单的模型是什么？其实就是 if 语句。定好 if 条件后，输入条件，输出结果，这种模型的特点是：规则是人定的。程序里有多少条规则，你就写多少条代码。每条规则都能看懂，每个结果都知道为什么出现。

但如果规则多到人写不完呢？如果规则本身是模糊的呢？这时候就需要另一种模型，不是人定规则，而是机器从数据里自己找规律。

### 什么是大语言模型

大语言模型（Large Language Model，LLM）是一种基于[人工神经网络](https://zh.wikipedia.org/wiki/%E4%BA%BA%E5%B7%A5%E7%A5%9E%E7%BB%8F%E7%BD%91%E7%BB%9C)的[语言模型](https://zh.wikipedia.org/wiki/%E8%AF%AD%E8%A8%80%E6%A8%A1%E5%9E%8B)，通过在海量文本数据上训练，学会理解和生成人类语言。它的“大”体现在三个方面「参数量大、训练数据量大、计算量大」。

但是，与模型不同的是，大模型并不是按照固定规则输出结果，它的本质是一个超级概率预测引擎。它并不真正“理解”世界，而是通过阅读海量文本，学习了人类语言的统计规律。它真正在做的事情，就是不断预测“下一个最可能出现的词（Token）是什么”。

好了，说到这里，我们还是很难理解大模型到底是什么。接下来，让我们一起开始构建一个大模型。在构建过程中，我们会接触到许多概念，理解每一步的变化，以及每一步存在的意义，从而最终重新认识这个黑匣子内部。

## 构建大模型

### 第一步：数据来源与文本整理

![训练数据整理流程](1.webp)

现在，我们需要通过各种方式，去搜集海量文本。那么这些内容去哪里搜集呢？

第一个是 Common Crawl：一个非营利组织，每月爬取整个互联网并免费公开。包含数百亿网页、PB 级原始数据。是目前绝大多数开源大模型（LLaMA、Falcon、Mistral 等）的数据基础。其次，爬虫也会访问各种公开资源，新闻机构、维基百科、论坛社区、公共书籍库、以及代码仓库（如 GitHub）等。

爬虫抓取回来的原始数据通常是 HTML 代码，里面混杂了大量对模型训练无用的“噪声”，因此我们需通过启发式算法来判断哪些是“内容”，哪些是“装饰元素”。去除导航、标签等内容。

其次，我们也要对语言进行过滤，如果想训练一个以中文为主的模型，那就需要设定一个阈值，比如中文内容占比 51% 以上的网页进行保留，否则就删除。因此会把大量英文、日文、韩文、阿拉伯文等其他语言的页面给过滤掉。如果对于多语言模型，则需要按照预设比例保留各语种的数据。

下一步就是去重，我们在网上经常能看到内容被转载过来，转载过去，因此，对搜集的语料，需要进行去重，来节省算力。去重有很多方法，使用哈希值进行精确和近似去重，也可以使用 URL 进行去重等。

去重后，内容还有大量低质量文本，比如一些机器生成的内容，营销号内容、垃圾页面等。高质量内容对模型质量非常重要，因此，有一种做法，训练一个小模型，对内容质量进行打分，先人工标注高质量、低质量，作为训练数据让机器去学习，然后对这个文本库进行扫描筛选。

最后，互联网内容里包含大量个人信息，以及暴力、仇恨言论等违法内容。这些进入训练数据会有法律风险和伦理问题。因此需要对这些隐私内容进行脱敏，对有害信息进行过滤，并且对于涉及到版权的内容进行处理。

经过以上步骤，我们终于将原始数据，筛选出高质量文本内容。内容涵盖人类知识的方方面面，可以称为超级百科全书了。

### 第二步：Tokenization（分词）

模型不能直接拿汉字、英文单词或表情符号做矩阵运算。文字进入模型之前，要先经过 Tokenization，被切成一个个 Token，再转换成数字编号。

Token 是模型处理文本的基本单位，但它不一定等于一个字或一个词。它可能是一个汉字、几个汉字、一个完整单词、单词的一部分、标点、空格，也可能是某些字符对应的字节片段。具体怎么切，取决于模型使用的分词器。

为什么不干脆按字或按词切？如果所有内容都切得很细，词表会比较小，也不容易遇到完全无法表示的新词，但同一句话会变成更长的 Token 序列，计算成本也会增加。如果把每个完整词都放进词表，常见词表达起来很省 Token，词表却会不断膨胀，新词、人名和拼写变化也很难全部收进去。

实际使用的分词方法通常会在两者之间折中。以 BPE（Byte Pair Encoding）及其变体为例，它会从较小的基本单元开始，反复合并语料中经常相邻出现的单元。常见片段可能合成一个 Token，少见内容则继续由更小的片段表示。

如果把这个过程展开，大致会经历下面几步：

1. 先把训练语料表示成较小的基本单元。不同实现可能从字符开始，也可能像字节级 BPE 一样从字节开始。
2. 统计语料中经常相邻出现的单元对。
3. 把选中的高频单元对合并成一个新 Token，并记录这条合并规则。
4. 重新统计合并后的语料，再选择下一组高频组合。
5. 达到预设词表规模后停止，分词器会用学到的规则编码新文本。

所以，BPE 学到的并不是一本由人手工整理的词典，而是一套从语料频率中产生的合并规则。高频内容往往能用更少的 Token 表示，低频内容也不会完全丢失，只是会被拆得更细。

英文单词 `flower` 可能被完整保留，也可能被切成 `flow` 和 `er`；中文里的“苹果”可能是一个 Token，也可能被拆成“苹”和“果”。现代字节级 BPE 还可能把某些字符表示成多个字节片段，所以不能简单认为中文一定从“一个汉字一个 Token”开始。

词表大小会在训练前确定。它不只取决于合并次数，还包含最初的基本单元和开始、结束等特殊 Token。词表太小，同样的内容需要更多 Token；词表太大，又会增加嵌入矩阵和输出层的规模。不同模型会选择不同的平衡点。

分词方式会直接影响三个方面：同样长度的上下文能装下多少内容，人名和生僻词是否容易被稳定表示，以及不同语言使用起来是否高效。一个分词器如果很少在中文语料上学习，中文往往会被切得更碎，但这只是语言能力的一部分，不能单独决定模型最终的中文水平。

经过分词后，“我喜欢吃苹果”可能被转换成类似下面的结果：

> 我 / 喜欢 / 吃 / 苹果 → [2769, 18526, 3221, 99814]

这里的切分和编号只是示意。换一个分词器，同一句话可能得到完全不同的 Token 和 ID。

![Tokenization 将文字转换为 Token ID](2.webp)

负责文字与 Token ID 相互转换的程序叫分词器（tokenizer）。输入模型时，它把文字编码成 Token ID；模型生成 Token ID 后，它再把这些编号解码成文字。我们看到回答逐段出现在屏幕上，也和这个解码过程有关，不过产品通常会把一个或多个 Token 合并后再传到界面，并不保证每次只显示一个 Token。

### 第三步：Embedding（向量嵌入）

分词之后，“我喜欢吃苹果”变成了 `[2769, 18526, 3221, 99814]`。这些数字只是词表里的编号，本身没有大小或远近的语义。假设“苹果”的 ID 是 1234，“香蕉”是 567，“汽车”是 8902，不能因为 567 离 1234 更近，就认为香蕉和苹果在语义上更接近。

模型接下来会通过 Embedding（向量嵌入）把每个 Token ID 映射成一个高维向量。

高维向量不是一个能被画出来的物理空间，而是一组用于计算的数字。比如一个 Token 用 4096 个数字表示，它就是一个 4096 维向量。单独拿出第 7 维或第 389 维，通常很难给它贴上“水果”“颜色”这样的固定标签，意义来自许多维度共同形成的表示。

Embedding 在模型中通常表现为一个矩阵。行数接近词表大小，列数是向量维度。假设词表有 100000 个 Token，向量维度是 4096，嵌入矩阵就有 100000 行、4096 列。Token ID 为 1234 时，模型会取出矩阵的第 1234 行作为它的初始向量。

同一个 Token ID 每次查到的初始向量相同。比如“苹果”单独出现，或出现在“我喜欢吃苹果”里，刚进入模型时取出的都是同一行。它在不同句子里为什么能表示不同含义，要靠后面的 Attention 和 FFN 一层层结合上下文。初始 Embedding 提供的是起点，不是这个词在当前句子里的最终解释。

训练开始时，这些数字通常由随机值初始化，之后会和模型的其他参数一起不断调整。

> 苹果 = [0.7292, -0.3786, 0.1065, 0.3674, 0.1902, -0.7881, ...]

![Embedding 将 Token 映射为向量](3.webp)

训练完成后，嵌入和后续网络会形成对预测有用的结构。出现在相似上下文中的 Token，表示中可能出现某些相近关系。不过，不能把它理解成“苹果和香蕉一定靠得近，苹果和汽车一定离得远”的固定地图。一个 Token 的真正含义，还会在后面的 Transformer 层中根据上下文继续变化。

![Token 从编号进入语义向量空间](4.webp)

#### 位置信息

只有 Token Embedding 还不够。“我喜欢吃苹果”和“苹果喜欢吃我”包含相同的 Token，如果不加入位置信息，注意力计算无法仅凭这些初始向量区分先后顺序。

位置编码有多种做法。原始 Transformer 使用正弦和余弦函数，为每个位置生成一个向量，再把它加到 Token Embedding 上。每个位置因此会得到不同的表示，但这些位置向量之间的距离并不是简单地随着位置间隔单调增大。

现在很多模型会使用 RoPE（Rotary Position Embedding，旋转位置编码）。它不是把另一个位置向量直接加到 Embedding 上，而是根据 Token 所在的位置旋转 Q 和 K，让后面的注意力分数能够反映相对位置信息。

无论具体采用哪种方案，目的都一样：让模型在处理 Token 关系时能够区分顺序和距离。

### 第四步：Attention（注意力）

现在，每个 Token 已经有了初始表示和位置信息，但它仍然没有结合当前句子的上下文。同一个“果”出现在“苹果”和“果然”里，最初取出的 Embedding 可以相同，经过上下文处理后却应该形成不同的表示。

Attention（注意力）负责让每个位置根据当前可见的其他位置，重新组合自己需要的信息。

比如这句话：

> 我昨天在图书馆看了一本书，它非常有趣。

处理“它”这个位置时，模型需要判断前面的哪些 Token 与它有关。“书”可能比“昨天”更相关，但这不是人提前写进程序的固定规则，而是由训练得到的参数和当前向量共同算出来的。

#### Q、K、V 是三种并行投影

每个位置的输入向量会分别乘以三个权重矩阵，得到 Q、K、V 三个向量：

> Q = XWQ  
> K = XWK  
> V = XWV

这三个计算从同一个输入 X 出发，并行进行，不是先算 V，再用 V 算 K，最后用 K 算 Q。

![每个 Token 的 Q、K、V 并行投影](image.webp)

Q（Query）可以暂时理解为“这个位置正在找什么”；K（Key）表示“这个位置可以怎样被匹配”；V（Value）则是匹配成功后参与汇总的内容。把它们类比成搜索词、索引和正文有助于建立直觉，但它们本质上都是训练得到的向量，没有人直接给某一维写上“代词”或“名词”的标签。

#### 注意力分数、掩码和加权汇总

一个位置的 Q 会与所有可见位置的 K 做点积。标准的缩放点积注意力还会把结果除以 √dₖ，避免向量维度较大时分数过大，让 Softmax 落入梯度很小的区域：

> Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V

![用 Q 与所有 K 计算注意力分数](image-2.webp)

只解码文本的模型通常使用 Causal Mask（因果掩码）。生成某个位置时，它只能看见自己和前面的 Token，未来位置会被遮住。经过 Softmax 后，可见位置得到一组总和为 1 的权重，再用这些权重对 V 做加权求和，得到该位置新的上下文表示。

可以把“它”这个位置的一次计算想象成下面这样，具体数字只是为了说明加权过程：

> “书”的权重 0.55，“图书馆”的权重 0.20，“昨天”的权重 0.02，其他可见位置合计 0.23。

模型会分别用这些权重乘以对应的 V，再把结果相加。新的向量不是直接复制“书”，而是混合了所有可见位置的信息，只是“书”在这次汇总中影响更大。

![根据注意力权重加权汇总 Value](image-3.webp)

以“它”为例，如果“书”获得较高权重，它的 V 就会对“它”的新表示产生更大影响。不过，“注意力权重高”不能直接等同于人类意义上的指代理解，它只说明这一层、这一个头在当前计算中更多地使用了那个位置的信息。

还有一个容易误解的地方。因果掩码允许后面的 Token 关注前面的 Token，却不会在后文出现后回头修改前面已经算好的隐藏状态。比如模型处理到“小李”时，“小李”可以关注前文的“他”；前面“他”的表示不会因为“小李”出现而被重新填空。继续生成时，模型会利用最后一个位置已经汇总的上下文信息预测下一个 Token。

#### 多头注意力

语言中的关系很多，一个位置可能同时需要处理语法、指代、位置和语义等信息。多头注意力会把 Q、K、V 的表示分成多个头，让每个头在较小的子空间里独立计算一组注意力分布。

以 GPT-3 175B 的配置为例，隐藏维度是 12288，共有 96 个注意力头，每个头的维度是 128。标准实现并不是先把原始输入向量固定切成 96 块，再让每一块只看自己的 128 维。更准确的理解是：完整输入先经过学习得到的 Q、K、V 投影，再被重排成 96 个头。每个头都来自完整输入的学习变换。

> 完整输入 X → Q/K/V 投影 → 重排为 96 个头 → 各头分别计算注意力 → 拼接 → 输出投影

![多头注意力并行计算并拼接](image-4.webp)

96 个头会并行计算，结果拼接回 12288 维后，再经过一次输出投影进行混合。设计者不会预先规定“第 1 个头只管指代，第 2 个头只管语法”。训练后有些头可能表现出较明显的模式，也有些头会混合多种关系，不能把每个头都解释成一个固定部门。

### 第五步：FFN（前馈神经网络）

Attention 让不同位置交换信息，但它的核心仍是对 V 做加权汇总。每个位置随后还会经过 FFN（Feed-Forward Network，前馈神经网络），对已经汇总到当前向量中的信息进行非线性变换。

FFN 对序列里的每个位置分别计算，所有位置使用同一组参数。一个位置进入 FFN 时，不会在这一步再次读取其他 Token，Token 之间的信息交换已经由 Attention 完成。

#### 神经元

人工神经元借用了生物神经元的名字，实际是一个数学计算单元。它接收一组输入，分别乘以权重，加上偏置，再经过激活函数：

> y = φ(w₁x₁ + w₂x₂ + … + wₙxₙ + b)

权重和偏置由训练调整，激活函数由模型架构决定。激活函数给网络带来非线性，否则连续多层线性变换仍然可以合并成一次线性变换，堆很多层也无法表达更复杂的关系。

如果只看一个简单例子，可以把“今天要不要出去跑步”写成几个输入：天气、空闲时间、睡眠情况和空气质量。每个输入乘以不同权重，加上偏置，再经过激活函数，就得到一个输出。这个例子只是在解释神经元怎样计算，并不代表大模型里真的存在一个专门负责“跑不跑步”的神经元。真实网络中的表示通常分布在许多神经元和层之间。

下面这张图用 Sigmoid 演示了一个神经元怎样把输入转成 0 到 1 之间的值。这里的输出只是在这个例子中落在 0 到 1，并不代表大模型 FFN 中每个神经元都在输出概率。实际模型可能使用 GELU、SwiGLU 等不同结构。

![一个神经元的基本计算过程](image-5.webp)

经典 Transformer 的 FFN 可以简化为：先把向量投影到更高维度，经过激活函数，再投影回原来的隐藏维度。

> 输入向量 → 升维投影 → 激活函数 → 降维投影 → 输出向量

很多早期模型的中间维度大约是隐藏维度的 4 倍，但这不是固定规则。现代模型的扩展比例、激活函数和门控方式都可能不同。

Attention 和 FFN 的分工可以这样记：Attention 负责让不同 Token 位置交换信息，FFN 负责在每个位置内部继续变换这些信息。模型的知识和能力分布在 Embedding、Attention、FFN 等大量参数中，不能把 FFN 简单当成一个独立的“知识仓库”。

![FFN 的升维、激活与降维过程](image-6.webp)

### Transformer Block：把这些零件组合起来

Attention 和 FFN 会与归一化、残差连接一起组成 Transformer Block。

归一化会把向量数值调整到更稳定的范围。不同模型可能使用 LayerNorm 或 RMSNorm，也可能把归一化放在 Attention、FFN 之前或之后。现在许多大语言模型采用前置归一化，但不能说所有现代模型都使用同一种结构。

残差连接会把子模块的输入加回输出。这样既能保留原有信息，也为训练中的梯度传播提供更直接的路径。一个采用前置归一化的 Block 可以简化成：

> h = x + Attention(Norm(x))  
> y = h + FFN(Norm(h))

模型会把许多 Transformer Block 依次堆叠。以 GPT-3 175B 为例，它有 96 层 Transformer，每层使用 96 个注意力头。头与头之间可以并行计算，层与层之间仍要依次执行，因为后一层需要前一层的输出。

随着层数增加，每个位置的表示会被反复更新，逐渐融合更广的上下文和更复杂的特征。研究中常能观察到不同层对不同类型信息的敏感程度不同，但“浅层只管词法，中层只管句法，深层只管推理”并不是一套固定分工，不能给每层预先安排明确职责。

经过最后一个 Block 后，模型得到的仍然是一组向量。对于下一个 Token 预测，系统会读取当前序列最后一个位置的隐藏状态，把它转换成词表上的分数。

![Transformer Block 的组成](image-7.webp)

### Logits：词表中每个 Token 的原始分数

最后一个位置的隐藏向量会经过输出投影，映射到整个词表。假设隐藏维度是 4096，词表有 100000 个 Token，输出层就会产生 100000 个 Logit，每个 Token 对应一个分数。

对词表中的第 i 个 Token，可以把它简化成一次向量点积：

> zᵢ = h · wᵢ + bᵢ

这里的 h 是最后一个位置的隐藏向量，wᵢ 和 bᵢ 是输出层中与这个 Token 对应的权重和偏置。模型会对词表中所有 Token 做同类计算，得到整张候选分数表。

Logit 可以是正数，也可以是负数。分数越高，表示模型在当前上下文下越倾向于选择这个 Token，但它还不是概率，也不能直接理解成模型对事实的信心。

### Softmax：把分数变成概率分布

Softmax 会把所有 Logit 转换成一组 0 到 1 之间、总和为 1 的数：

> P(tokenᵢ) = e^(zᵢ/T) / Σⱼ e^(zⱼ/T)

这里的 zᵢ 是第 i 个 Token 的 Logit，T 是 Temperature（温度）。得到的概率表示：在模型已经看到当前上下文的条件下，每个 Token 作为下一项的相对可能性。这是模型学到的条件概率分布，不等于答案在现实世界中正确的概率。

#### Temperature：改变分布的形状

温度会在 Softmax 前缩放 Logit：

- T = 1 时，不做额外缩放。
- 0 < T < 1 时，分布会更尖，高分 Token 的优势更明显，输出通常更稳定。
- T > 1 时，分布会更平，低分 Token 获得更高的相对机会，输出通常更多样。

温度很低时，结果会逐渐接近只选最高分 Token；温度很高时，分布会趋向均匀。实际系统常把“温度为 0”实现为直接选择最高分项，而不是代入公式计算。

降低温度只能减少采样随机性，不能给模型补充知识，也不能保证事实、代码或推理更正确。

### Sampling：怎样从概率分布中选一个 Token

得到概率分布后，系统还要决定怎样选出下一个 Token。它可以直接选择概率最高的一项，也可以先限制候选范围，再按剩余概率随机采样。

| 选择方式 | 做法 | 特点 |
|---|---|---|
| Greedy（贪心） | 每次选择概率最高的 Token | 结果较稳定，但可能重复，也可能过早走进局部最优 |
| Top-k Sampling | 只保留概率最高的 k 个 Token，再重新归一化和采样 | 候选数量固定，简单直接 |
| Top-p Sampling | 按概率从高到低累加，只保留累计概率达到 p 的最小候选集合 | 模型越确定，候选集合通常越小；越不确定，集合通常越大 |

温度、Top-k 和 Top-p 可以单独使用，也可以组合使用。不同产品会选择不同的默认策略，有些参数甚至不会直接暴露给用户，所以不能把某一种组合说成所有系统的固定流水线。

Top-k 保留的候选数量固定。无论模型很确定还是很犹豫，k 设为 50 时都会留下 50 个。Top-p 看的是累计概率：如果前几个 Token 已经集中了大部分概率，候选集合会很小；如果概率比较分散，就会保留更多 Token。它调整的是候选范围，并不会判断候选内容是否符合事实。

无论采用哪种方法，这一步最终只会选出一个 Token。

![Logits、Softmax 与 Sampling 的关系](image-8.webp)

### 自回归：把输出继续放回输入

第一个 Token 选出来后，会被追加到原来的序列末尾，模型再根据更新后的上下文预测下一个：

> “我喜欢吃苹果” → 选出“很”  
> “我喜欢吃苹果很” → 选出“好”  
> “我喜欢吃苹果很好” → 选出“吃”

模型不断把自己的输出追加到输入中，再生成下一项，这种方式叫自回归生成。每一步只直接选择一个 Token，一整句话或一整段回答是在许多轮之后逐渐形成的。

生成通常会在几种情况下停止：模型生成了 EOS（End of Sequence，序列结束）Token，系统遇到预设的停止字符串，或者达到最大输出长度。

![自回归生成循环](image-9.webp)

### KV Cache：避免重复计算前文

如果每生成一个 Token，都从头计算整段上下文，会重复做很多工作。前文没有发生变化，它在每一层产生的 K 和 V 也不会因为末尾多出一个新 Token 而改变。

还是用“我喜欢吃苹果”举例。第一轮处理这段输入时，各层会为已有 Token 计算 K 和 V。假设下一项生成了“很”，第二轮只是在末尾多了一个 Token，前面几个 Token 的 K 和 V 与上一轮相同。如果不保存，它们就会被再次计算；有了缓存，模型只需要补上“很”在每一层的新结果。

KV Cache 会为每一层保存已经计算过的 K 和 V。下一轮生成时，新 Token 仍然要通过所有 Transformer 层，并计算自己的 Q、K、V；前面 Token 的 K 和 V 可以直接从缓存中读取。新 Token 的 Q 再与“所有旧 K 加上自己的 K”计算注意力，并对对应的 V 做加权汇总。

Q 通常不需要为旧 Token 保留，因为下一步只需要为最新位置提出新的查询。K 和 V 则要继续留着，供后续 Token 查询。

从单步注意力计算看，假设当前上下文长度为 N，完全重算整个序列需要处理约 N² 个位置关系；使用 KV Cache 后，只计算新位置对已有位置的注意力，这部分约为 N。这里说的是每一步的注意力计算量，不代表整个生成过程的耗时会严格按同样比例下降。缓存还会占用显存，并随着上下文变长而继续增长。

至此，一次生成过程就完整了：文字经过 Tokenization 变成编号，Embedding 把编号变成向量，位置信息和多层 Transformer 让表示结合上下文，输出层再把最后一个位置映射成词表概率，采样得到一个 Token，然后通过自回归继续下一轮。

这条管道里到处都是已经训练好的权重：Embedding 矩阵、Q/K/V 投影、FFN 和输出层。它们最初从哪里来，又是怎样在海量文本中被一点点调整出来的，就是下一篇“从海量文本到基座模型”要回答的问题。

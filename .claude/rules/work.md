# Work 模块规则（src/content/work/）

做新作品集项目、或修改已有项目时，按这套约定执行。规则是从 2026-09 的整批改版里沉淀出来的。

## 1. 目录与字段

- 一个项目 = `src/content/work/<slug>/`：`index.md` + 全部图片
- frontmatter：`title` / `date` / `summary` / `cover` / `metaLeft` / `metaRight` / `type` / `period` / `status`
  - `type` / `period` / `status` 是后加的可选字段（schema 在 `src/content.config.ts`），**不在 Keystatic 后台表单里，只能在 md 里改**
  - `metaLeft` 写职责标签，用 ` / ` 分隔，如 `产品 / 交互 / 视觉`
  - `period` / `status` 的值**一律取自板子第一张底部的信息条**（那是权威口径）；没有就留空，卡片会自动不显示那一行

## 2. 图片管线

- 源图：设计工具导出的 PNG（常见 3840/4396 宽）
- 站内：转 **2560 宽 webp，quality 92，method 6**（PIL）
- 命名：数字序号（`01.webp`… 或沿用既有编号）；封面单独存 `cover.webp`
- 详情页显示宽 1000px（shell 1032 − 左右各 16 内边距），别改这个数字除非同步改 `EssayLayout.astro`

## 3. 封面裁切规则

- **列表封面 = 裁切版** `cover.webp`：裁掉板子底部的「项目周期/协作团队/项目状态」信息条
  - 有分隔线：在分隔线**上方** 1–2px 处裁（曾见于 y≈2414 的 4396×3072 模板）
  - 无分隔线：取「最后一行正文」与「信息条首行」的中点裁
- **详情页第一张 = 完整版**（带信息条），文件名照 md 里的引用
- frontmatter `cover: "cover.webp"`

## 4. 列表卡片（src/pages/work/index.astro）

- 结构：标题 → 类型 chip（实心）+ 职责标签（彩色描边）→ 项目周期/项目状态 → 封面
- 类型词表：`AI` / `APP` / `中后台` / `运营`（实心 chip，`--color-interactive` 反色）
- 职责标签颜色**按关键词映射**（`roleTagClass` 函数），新关键词要在这里加颜色，深浅两套：
  | 关键词 | 浅色 | 深色 | 语义 |
  |---|---|---|---|
  | 产品 | #b1402a | #e0907c | 红 |
  | 交互 | #347347 | #86c194 | 绿 |
  | 视觉 | #34659b | #86aede | 蓝 |
  | 动效 | #b06a2a | #e0a06a | 琥珀 |
  | 可视化 | #6f56a3 | #b39bd6 | 紫 |
  | 设计规范 | #2f7a72 | #7fc4ba | 青 |
  | 组件库 | #a84a68 | #d996ac | 玫红 |
  | 其它 | 中性描边（不设色） | — | — |
- 排序：`WORK_ORDER` 数组显式控制；没写进去的条目按 date 倒序垫后
- 列表有右侧粘性目录（≥88em 显示、滚动高亮、点击跳转），条目 `id` = slug，不用管
- 筛选用 tab（全部/AI 应用/中后台/App/运营活动），分类映射在 `projectCategories` 函数里

## 5. 详情页（EssayLayout 的 work 作用域）

- 页头（标题）与版面图左对齐；**不显示日期**（date 只用于排序兜底和 og 元信息）
- 版面图 1000px 宽、板间 32px、每块板 1px 细环（`--color-image-ring`，深浅都生效）
- 可选文字介绍（现在的标准格式，见第 6 条）：文字块与图同宽同左缘

## 6. 详情页文字介绍格式（标题下、第一块板之前）

```
（介绍段：一段话，2–3 行）

**项目职责**

1. …（做了什么；结果/数据融在句末）
2. …
3. …
```

- **职责合并成 3 条左右**，成果/贡献不单独成节，量化结果挂到对应职责尾部（如「…；上线后用户留存率提升 30%+」）
- 成果若与职责同义（换词重述）就删，不要重复
- 每条以动词开头，条目之间不重复用同一个动词
- 全半角：中英文/数字之间加空格（App、AI、40+ 高保真）；引号用「」

## 7. 文案红线

- **作品集语言，不是汇报**：不写时间线、日期、流水账
- **不编造数据和效果**：数字必须来自真实记录（业务方/后台/上线数据）；记不清就跳过
- 术语口径与板子一致，板子信息条优先

## 8. 操作注意事项（给 AI）

- 改 frontmatter 用 Edit 工具逐行改；用脚本重写 md 时先留备份，改完检查 frontmatter 是否完整（曾出过被覆写的 bug）
- 大批量替换图片后 dev server 可能 500：重启 `npm run dev`；仍报错就删 `.astro` 缓存再起
- 每次改完：截图验证（headless Chrome）+ `npm run build`
- 推送由用户自己来（GitHub Desktop），Vercel 自动部署
